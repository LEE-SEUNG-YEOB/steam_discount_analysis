## 사용 가이드

### 작업 순서

1. **보완 A (용어 통일)** — 가장 빠름, 0.5일
2. **보완 B+C (리뷰 재수집)** — ROI 최고, 1단계는 코드 작성 / 2단계는 분석

### 원칙

- **한 세션에 하나의 보완 작업만.** 작업이 끝나면 새 세션 시작 (긴 컨텍스트는 토큰 낭비).

- 코드 작성 전에 항상 "먼저 ~를 보여줘" 단계 두기. 한 번에 다 하라고 시키면 잘못된 방향으로 가서 토큰 더 씀.
- 결과 파일 저장 전에 미리보기 받고 OK 확인 → 그 다음 저장.

## 2. 보완 B+C 1단계 — 리뷰 재수집

**목표:** 기존 `review_daily.csv`는 일별 집계라 playtime이나 voted_up 컬럼을 추가할 수 없음. 개별 리뷰 단위로 재수집하는 새 노트북 작성.

```
보완 B와 C 작업의 1단계로, Steam appreviews API 재수집 코드를 작성할 거야.

배경:
- 기존 data/review_daily.csv는 일별 집계 데이터라서 개별 리뷰의 플레이타임, 추천 여부 같은 정보를 담을 수 없음
- 개별 리뷰 단위 데이터를 새로 수집해서 별도 파일로 저장해야 함
- 기존 review_daily.csv는 그대로 두고, 새 파일을 추가하는 방식

목표 — 다음 필드를 포함한 개별 리뷰 데이터 수집:
- review_id (recommendationid)
- app_id, app_name, genre
- timestamp_created (리뷰 작성 시각, Unix timestamp)
- voted_up (true/false, 추천 여부)
- playtime_at_review_min (리뷰 작성 시점 플레이타임, 분 단위)
- playtime_forever_min (전체 플레이타임, 분 단위)
- language
- review_length (리뷰 본문 글자 수 — 본문 자체는 저장하지 말고 길이만)

요구사항:

1. 먼저 notebooks/05_reviews.ipynb의 기존 수집 코드를 그대로 보여줘. 어떤 API 엔드포인트, 어떤 파라미터, 어떤 페이지네이션 방식을 쓰는지 파악할 수 있게.

2. 기존 코드를 참고해서 새 노트북 작성: notebooks/05b_reviews_individual.ipynb
   (기존 05_reviews.ipynb는 절대 덮어쓰지 말 것)

3. Steam appreviews API 옵션:
   - https://store.steampowered.com/appreviews/{appid}?json=1
   - filter=recent (시간순) 또는 updated
   - language=all
   - filter_offtopic_activity=1 (review bombing 완화, 기본값)
   - num_per_page=100 (최대)
   - cursor 파라미터로 페이지네이션 (다음 cursor가 이전과 같으면 중단)
   - day_range는 사용하지 말 것 (전체 기간 필요)

4. 안정성:
   - 각 API 호출 사이 time.sleep(1.0) 이상
   - HTTP 에러 발생 시 최대 3회 재시도, 지수 백오프
   - 게임 단위로 중간 저장 (한 게임 끝날 때마다 임시 CSV에 append)
   - 이미 수집된 게임은 스킵하는 resume 기능

5. 진행 상황 출력:
   - 현재 처리 중인 게임명, app_id
   - 게임별 누적 리뷰 수
   - 전체 진행률 (n/50)

6. 출력:
   - 최종 파일: data/review_individual.csv
   - 게임당 리뷰 수가 너무 많으면(예: 10만건 이상) 최근 N년 또는 최근 M개로 제한할지 미리 의논
   - target_games.csv의 50개 게임 모두 처리

7. 노트북 구성:
   - 셀 1: 라이브러리 import
   - 셀 2: 설정값 (sleep 시간, 게임당 최대 리뷰 수, 출력 경로)
   - 셀 3: 단일 게임 수집 함수
   - 셀 4: 전체 게임 루프 (resume 기능 포함)
   - 셀 5: 수집 결과 요약 (게임별 리뷰 수, 전체 리뷰 수, 결측치 확인)

⚠️ 작업 순서:
1. 먼저 기존 05_reviews.ipynb 코드 구조만 보여줘
2. 새 노트북 구조 설계안(셀 구성 + 함수 시그니처)을 마크다운으로 제시
3. 내가 OK 하면 그때 셀별로 작성
4. 셀 작성할 때마다 작성 결과 보여주고 진행
5. 모든 셀이 완성되면 마지막에 노트북 파일 저장

⚠️ 절대 실제 실행은 하지 마. 코드만 작성. 실행은 내가 직접 한다.
```

## 부록 B: 에이전트 사용 팁

### 토큰 절약 팁

- **세션 분리**: 보완 A / B / C+분석 / D / 마무리 각각 새 세션. 한 세션이 너무 길어지면 컨텍스트 토큰 폭증.
- **읽기 범위 제한**: "data/\*.csv 읽어줘"는 위험. 항상 `head(3)`, `.columns`, `.dtypes`만 요청.
- **노트북은 셀 단위로**: ipynb 전체를 한 번에 읽지 말고 마크다운 셀 + 첫 코드 셀 + 마지막 출력만.
- **진행 중간 보고 받기**: "다 됐어"보다 "1단계 했고 결과 이래"가 토큰 효율적 (실수 조기 발견).
