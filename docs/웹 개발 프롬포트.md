# Steam 할인 분석 프로젝트 — 기술스택 + Agent 개발 지시서 최종 수정본

## 0. 문서 목적

이 문서는 Steam 할인 분석 프로젝트의 웹앱 구현을 위한 **기술스택 선정안 + VSCode Agent AI 개발 지시서**입니다.

기존 서비스 기획/발표 구성 정리본은 그대로 유지하고, 이 문서는 실제 개발 단계에서 참고하는 기술 문서로 사용합니다.

이번 수정본에는 다음 사항을 반영했습니다.

- Streamlit 제외
- Next.js + 정적 JSON 구조 확정
- 탭3 할인 전략 시뮬레이터는 다른 팀원이 담당
- 사용자는 탭1 Dashboard, 탭2 Game Report, Overview, Methodology, 데이터 JSON 생성 담당
- 3일 안에 몰아서 개발해야 하므로 Day 단위 일정 제거
- 해야 할 작업을 우선순위 순서로 정리
- `review_individual.csv` 대용량 처리 안내 추가
- TypeScript 타입 정의 명시
- 차트 라이브러리는 Recharts 기본 추천
- shadcn/ui 초기화 명령 추가
- npm scripts 추가
- 에러 상태 처리 지침 추가

## 2. 차트 라이브러리 결정

기본 추천은 **Recharts**입니다.

이유:

- React/Next.js와 자연스럽게 맞음
- TypeScript에서 쓰기 편함
- 막대그래프, 선그래프, 산점도 등 현재 프로젝트에 필요한 차트는 충분히 구현 가능
- ECharts보다 옵션 객체가 단순함
- 번들 크기와 구현 난이도 측면에서 부담이 적음

```text
기본 선택: Recharts
예외: 이미 ECharts로 구현을 시작했거나 복잡한 인터랙션이 필요하면 ECharts 유지 가능
```

이번 프로젝트에서 필요한 차트는 대부분 다음 수준입니다.

```text
- 장르별 반응률 막대그래프
- 할인율 구간별 반응률 차트
- 시즌/비시즌 비교 차트
- 게임별 할인 이벤트 추이
- 긍정률 변화 비교
```

따라서 Recharts로 충분합니다.

## 3. 핵심 구조

이번 웹앱은 백엔드 서버를 따로 두지 않고, Python으로 분석 결과를 JSON으로 미리 만들어둔 뒤 Next.js에서 읽어오는 구조로 갑니다.

```text
원본 CSV
  ↓
Python 전처리 스크립트
  ↓
public/data/*.json 생성
  ↓
Next.js 웹앱에서 JSON fetch/import
  ↓
대시보드 / 게임별 리포트 / 전략 시뮬레이터 표시
```

---

## 4. Python의 역할

Python은 웹앱 실행 중 서버 역할을 하지 않습니다.

Python의 역할은 다음입니다.

```text
- 원본 CSV 읽기
- 분석 결과 집계
- 게임별 리포트용 수치 계산
- 장르별 중앙값 계산
- 시즌/비시즌 반응률 계산
- 긍정률 변화 그룹 생성
- 앱에서 사용할 JSON 생성
```

즉, Python은 **데이터 가공 도구**이고, 실제 웹 화면과 사용자 인터랙션은 Next.js가 담당합니다.

## 14. `types/index.ts` 필수 정의

Agent AI가 `any`를 남발하지 않도록 JSON 구조에 맞는 타입을 명시합니다.

```ts
export type Genre =
  | "Action"
  | "RPG"
  | "Adventure"
  | "Casual/Lightweight"
  | "Strategy/Simulation";

export type Confidence = "strong" | "exploratory";

export interface SummaryData {
  games_count: number;
  discount_events_collected: number;
  valid_events: number;
  reviews_count: number;
  main_message: string;
}

export interface GameInfo {
  app_id: number;
  name: string;
  genre: Genre;
  release_date?: string;
  price?: number;
  tags?: string[];
}

export interface GameReport {
  app_id: number;
  name: string;
  genre: Genre;
  valid_event_count: number;
  avg_discount_rate: number;
  max_discount_rate: number;
  avg_response_rate: number;
  avg_retention_rate: number;
  genre_median_response: number;
  overall_median_response: number;
  season_response?: number;
  nonseason_response?: number;
  discount_frequency: number;
}

export interface DashboardEvent {
  event_id: string;
  app_id: number;
  game_name: string;
  genre: Genre;
  is_season_sale: boolean;
  playtime_filter: "all" | "2h" | "10h";
  discount_rate: number;
  response_rate_all: number;
  retention_rate: number;
  positive_rate_before?: number;
  positive_rate_during?: number;
  positive_rate_delta?: number;
  sentiment_group?: "positive_rate_up" | "positive_rate_flat" | "positive_rate_down";
  valid_event_count_for_genre?: number;
}

export interface SimulatorRule {
  id: string;
  condition: string;
  message: string;
  evidence: string;
  chart?: string;
  confidence: Confidence;
}
```

탭3 팀원은 이 타입에 맞춰 `SimulatorInput`, `SimulatorResult`를 추가해도 됩니다.

## 18. 평판 변화 그룹 생성 규칙

탭1 Dashboard에 평판 변화 필터를 넣기 위해 `positive_rate_delta`를 기준으로 `sentiment_group`을 생성합니다.

```text
positive_rate_delta > 0.005
→ positive_rate_up

-0.005 <= positive_rate_delta <= 0.005
→ positive_rate_flat

positive_rate_delta < -0.005
→ positive_rate_down
```

표시 이름:

```text
positive_rate_up → 긍정률 상승
positive_rate_flat → 긍정률 유지
positive_rate_down → 긍정률 하락
```

# Part L. 발표 질문 대비 답변

## 42. 왜 Streamlit이 아니라 Next.js인가요?

> Streamlit은 빠른 분석 공유에는 좋지만, 이번 프로젝트에서는 최종 결과물을 실제 웹서비스 형태로 보여주는 것이 목표였습니다. 그래서 UI/UX 완성도와 포트폴리오 활용성을 높이기 위해 Next.js 기반으로 구현했습니다.

---

## 43. 백엔드는 왜 없나요?

> 현재 프로젝트는 실시간 서버 계산보다 이미 분석된 결과를 활용하는 것이 핵심입니다. 따라서 Python으로 데이터를 사전 가공해 JSON으로 만든 뒤, Next.js에서 이를 읽어 시각화하는 정적 데이터 기반 구조로 구현했습니다. 이 방식이 발표 시연 안정성도 높습니다.

---

## 44. 이건 예측 모델인가요?

> 아닙니다. 정확한 매출이나 반응률을 예측하는 모델은 아닙니다. 과거 유사 조건에서 관찰된 패턴을 기반으로 할인 전략의 리스크를 참고할 수 있게 만든 분석 기반 진단 도구입니다.
