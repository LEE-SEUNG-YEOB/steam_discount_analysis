# Steam 할인 분석 프로젝트 — 웹앱 시연 최종 정리본

## 1. 최종 방향

이번 프로젝트의 시연 웹앱은 기존 옵션 2, 3, 4를 합친 형태로 가는 것이 가장 적절합니다.

- Option 2: Steam 할인 전략 시뮬레이터
- Option 3: 게임별 할인 분석 보고서 생성기
- Option 4: 인터랙티브 분석 대시보드

다만 세 기능을 모두 풀버전으로 구현하면 범위가 너무 커지므로, 다음처럼 **하나의 웹앱 안에 3개 페이지/탭**으로 구성하는 것이 가장 안전합니다.

> 분석 대시보드 + 게임별 리포트 생성기 + 할인 전략 시뮬레이터

---

## 2. 앱 이름

### 최종 추천

> **Steam 할인 전략 분석 도구**

### 대체 이름

> Steam 할인 전략 리포트 & 시뮬레이터

> Steam 할인 반응 분석 대시보드

가장 추천하는 이름은 **Steam 할인 전략 분석 도구**입니다.

이유는 단순 차트 대시보드가 아니라 다음 세 가지 기능을 모두 포함하기 때문입니다.

1. 전체 분석 결과 확인
2. 특정 게임 리포트 생성
3. 할인 조건별 전략 리스크 진단

---

## 3. 앱 한 줄 설명

> Steam 할인 데이터를 기반으로 전체 분석 결과를 확인하고, 특정 게임의 할인 리포트를 생성하며, 할인율·시즌성·장르 조건에 따른 전략 리스크를 진단하는 웹앱.

---

## 4. 앱의 핵심 메시지

이 앱은 단순히 다음을 보여주는 도구가 아닙니다.

> 할인하면 반응이 증가한다.

이 문장은 너무 뻔하게 보일 수 있습니다.

앱의 핵심 메시지는 다음이어야 합니다.

> 할인은 단기 유입을 만들지만, 그 유입이 장기 유지나 긍정적 경험으로 이어지는지는 조건에 따라 달랐다.

즉, 이 앱은 할인 효과를 단순히 “좋다/나쁘다”로 판단하는 도구가 아니라 다음을 함께 보여주는 도구입니다.

- 단기 반응
- 유지율
- 긍정률 리스크
- 장르별 탐색 패턴
- 할인율 영향
- 시즌성 영향
- 반복 할인 피로도 가능성

---

```text
Steam 할인 전략 분석 도구

[탭 1] 분석 대시보드

- 실제 수치 기반 자동 분석 코멘트
- 리포트 다운로드

- 근거 차트 및 통계 결과 표시

- 전략 추천 문장 출력
```

# Part A. 왜 2+3+4 결합이 적절한가?

## 6. 발표 흐름이 자연스러움

발표에서 다음 흐름으로 설명할 수 있습니다.

> 먼저 대시보드에서 전체 분석 결과를 확인하고,  
> 특정 게임을 선택해 자동 리포트를 생성하며,  
> 마지막으로 할인율·시즌성·장르 조건을 바꿔 전략을 시뮬레이션합니다.

즉, 단순히 차트를 보여주는 것이 아니라 다음 흐름이 생깁니다.

> 전체 분석 → 개별 게임 적용 → 전략 진단

이 흐름은 발표와 시연 모두에 적합합니다.

---

## 7. 평가 기준에 잘 맞음

수업 평가 항목을 기준으로 보면 2+3+4 결합은 다음처럼 대응됩니다.

| 앱 구성 | 평가에 도움 되는 부분 |
|---|---|
| 분석 대시보드 | 분석 깊이, 시각화, 통계 검증 |
| 게임별 리포트 생성기 | Project output, 결과물 완성도 |
| 전략 시뮬레이터 | 창의성, 서비스성, 시연 효과 |

즉, 하나의 앱으로 다음 항목을 모두 커버할 수 있습니다.

- 창의성
- 난이도
- 결과물 완성도
- 발표 시연성

---

## 8. 서비스 시나리오가 명확함

3개 이하의 서비스 시나리오를 구성해야 하는 조건에도 잘 맞습니다.

| 시나리오 | 앱 탭 |
|---|---|
| 전체 분석 결과 확인 | 분석 대시보드 |
| 특정 게임 리포트 생성 | 게임별 리포트 생성기 |
| 할인 조건별 전략 진단 | 할인 전략 시뮬레이터 |

## 13. Placebo Test의 위치

Placebo Test는 핵심 인사이트가 아니라 **지표 검증**으로 다루는 것이 좋습니다.

### 잘못된 설명

> 할인 기간 반응 증가가 통계적으로 확인됐다.

이 표현은 너무 뻔하거나 과장되어 보일 수 있습니다.

### 추천 설명

> Placebo Test는 우리가 정의한 Engagement 반응률 지표가 실제 할인 이벤트를 감지할 수 있는지 확인하기 위한 지표 검증 단계입니다.

### 탭 1에서의 표시 방식

```text
지표 검증: Placebo Test

진짜 할인 기간의 반응률은 비할인 랜덤 기간보다 높게 나타났습니다.
이는 Engagement 반응률 지표가 할인 이벤트를 구분할 수 있음을 보여줍니다.
단, 이는 완전한 인과관계 증명이 아니라 지표 타당성 확인입니다.
```

# Part C. 탭 2 — 게임별 리포트 생성기

## 15. 탭 2의 역할

탭 2는 특정 게임을 선택하면 해당 게임의 할인 패턴과 반응률을 요약한 자동 리포트를 생성하는 기능입니다.

이 탭은 앱의 **메인 output** 역할을 합니다.

---

## 16. 탭 2의 핵심 리스크

탭 2에서 가장 큰 리스크는 자동 해석 문장이 너무 템플릿처럼 보이는 것입니다.

### 나쁜 예시

```text
선택한 게임은 같은 장르 평균과 비교했을 때 할인 이벤트 반응률이 높은 편입니다.
```

이렇게 모든 게임에 비슷한 문장이 나오면 교수님이 다음처럼 의심할 수 있습니다.

> 이거 그냥 if-else로 출력하는 것 아닌가요?

따라서 자동 문장에는 반드시 **그 게임의 실제 수치**가 들어가야 합니다.

---

## 17. 탭 2 자동 문장 작성 원칙

자동 문장은 다음 구조를 가져야 합니다.

> 템플릿 문장 + 실제 수치 + 비교 기준 + 해석

즉, 단순히 “높다/낮다”가 아니라 다음 값을 넣어야 합니다.

- 해당 게임의 유효 할인 이벤트 수
- 평균 반응률
- 같은 장르 중앙값
- 전체 중앙값
- 시즌 세일 반응률
- 비시즌 할인 반응률
- 평균 할인율
- 최고 할인율
- 할인 빈도

---

## 18. 탭 2 좋은 자동 문장 예시

```text
Terraria는 총 8건의 유효 할인 이벤트가 있었고, 평균 반응률은 0.18입니다.
이는 같은 장르 중앙값 0.27보다 낮은 편입니다.
다만 시즌 세일 4건의 평균 반응률은 0.22로, 비시즌 할인 0.14보다 높게 나타났습니다.
따라서 이 게임은 시즌 할인에서 단기 반응이 더 크게 나타나는 패턴을 보입니다.
```

또는

```text
선택한 게임은 총 6건의 유효 할인 이벤트가 있으며, 평균 할인율은 42%, 최고 할인율은 70%입니다.
평균 반응률은 0.31로 전체 게임 중앙값 0.24보다 높은 편입니다.
다만 할인 후 14일 유지율은 같은 장르 평균보다 낮아, 단기 유입 이후 유지 전략이 필요합니다.
```

---

## 19. 탭 2 입력값

- 게임 선택
- 비교 기준 선택
  - 같은 장르 평균
  - 전체 게임 평균
- 보고서 형식 선택
  - 화면 출력
  - Markdown 다운로드

|---|---|

## 22. 탭 2 발표 멘트

> 두 번째 탭은 게임별 리포트 생성기입니다.  
> 사용자가 게임을 선택하면 과거 할인 이력, 할인 이벤트별 반응률, 같은 장르 평균과의 비교를 자동으로 정리합니다.  
> 자동 해석 문장에는 해당 게임의 실제 이벤트 수, 평균 반응률, 장르 중앙값, 시즌/비시즌 비교 수치가 포함되기 때문에 단순 템플릿이 아니라 실제 데이터 기반 리포트로 활용할 수 있습니다.

# Part D. 탭 3 — 할인 전략 시뮬레이터

## 23. 탭 3의 역할

탭 3은 장르, 할인율, 시즌 여부, 할인 빈도, 전략 목표 등을 입력하면 할인 전략의 리스크와 방향성을 진단하는 기능입니다.

다만 이 탭은 정확한 예측 모델처럼 보이면 안 됩니다.

따라서 다음 표현은 피해야 합니다.

```text
예상 반응률은 37.2%입니다.
```

이런 표현을 쓰면 교수님이 다음 질문을 할 수 있습니다.

> 이 예측 모델의 정확도는 어떻게 검증했나요?

---

## 24. 탭 3의 표현 원칙

탭 3은 다음처럼 표현해야 합니다.

> 과거 유사 조건 기준 경향입니다.

## 26. 전략 목표 입력의 사용 방식

전략 목표 입력은 반드시 출력에 반영되어야 합니다.  
그렇지 않으면 교수님이 다음처럼 물을 수 있습니다.

> 이 입력값은 어디에 쓰이나요?

전략 목표는 계산값을 크게 바꾸는 입력이라기보다, **출력 리포트의 해석 우선순위와 강조점을 바꾸는 입력**으로 쓰면 됩니다.

### 추천 방식

```text
목표 = 단기 유입
→ 반응률 관련 코멘트 먼저 표시

목표 = 장기 유지
→ 유지율 리스크 관련 코멘트 먼저 표시

목표 = 만족도 관리
→ 긍정률 리스크 관련 코멘트 먼저 표시
```

## 27. 전략 목표별 출력 예시

### 27.1 단기 유입 선택 시

```text
선택 목표: 단기 유입

높은 할인율과 시즌 세일 조건은 단기 리뷰 반응을 높일 가능성이 있습니다.
다만 유지율과 긍정률 리스크는 함께 확인해야 합니다.
```

### 27.2 장기 유지 선택 시

```text
선택 목표: 장기 유지

이 조건은 단기 반응은 높을 수 있지만, 시즌 세일의 경우 할인 후 유지율이 낮아질 가능성이 있습니다.
장기 유지를 목표로 한다면 비시즌 할인이나 할인 후 콘텐츠 업데이트 전략을 함께 고려하는 것이 좋습니다.
```

### 27.3 만족도 관리 선택 시

```text
선택 목표: 만족도 관리

선택한 조건은 단기 유입에는 유리할 수 있지만, 일부 장르에서는 긍정률 하락 경향이 관찰되었습니다.
만족도 관리를 목표로 한다면 높은 할인율보다 유입 후 리뷰 품질과 기대치 관리를 함께 고려해야 합니다.
```

## 30. 탭 3에서 반드시 추가해야 할 것: 근거 표시

룰 기반 시뮬레이터에서 교수님이 가장 쉽게 물을 수 있는 질문은 다음입니다.

> 이 규칙은 어디서 나온 건가요?

따라서 각 진단 결과 옆에 반드시 근거를 붙이는 것이 좋습니다.

### 예시 1

```text
진단: 높은 할인율은 단기 반응을 높일 가능성이 있습니다.

근거:
본 분석에서 할인율 구간별 반응률 차이가 유의하게 나타났습니다.
Spearman ρ=0.18, p=0.004, chart13 기준
```

### 예시 2

```text
진단: 시즌 세일은 단기 유입형 전략에 가깝습니다.

근거:
시즌 세일은 비시즌보다 반응률은 높고 유지율은 낮은 경향을 보였습니다.
단, p-value가 충분히 낮지 않아 탐색적 패턴으로 해석합니다.
```

### 예시 3

```text
진단: Action 장르는 만족도 리스크를 함께 확인해야 합니다.

근거:
Action은 반응률이 높게 나타났지만, 긍정률 하락 경향도 함께 관찰되었습니다.
단, 신뢰구간이 0을 포함하므로 확정 결론이 아니라 탐색적 경향입니다.
```

## 31. 탭 3에서 반드시 추가해야 할 것: 표본 크기 경고

사용자가 특정 장르를 선택했을 때, 해당 장르의 표본 수가 작다면 경고를 보여주는 것이 좋습니다.

### 예시

```text
주의:
선택한 장르의 유효 할인 이벤트 수가 다른 장르보다 적어 결과 변동성이 클 수 있습니다.
따라서 이 결과는 확정 결론이 아니라 탐색적 경향으로 해석해야 합니다.
```

### Action 선택 시 예시

```text
주의:
Action 장르는 유효 이벤트 수가 상대적으로 적어 결과 변동성이 클 수 있습니다.
따라서 Action 관련 결과는 확정 결론이 아니라 탐색적 경향으로 해석해야 합니다.
```

이런 경고가 있으면 오히려 프로젝트 신뢰도가 올라갑니다.

교수님 입장에서는 다음처럼 볼 가능성이 있습니다.

> 표본 수 한계를 알고 있네.

## 32. 탭 3 최종 출력 예시

```text
전략 유형: 단기 유입형 + 만족도 리스크 주의

선택 조건:
- 장르: Action
- 할인율: 70%
- 할인 시점: 시즌 세일
- 연간 할인 빈도: 3회 이상
- 전략 목표: 만족도 관리

진단:
높은 할인율과 시즌 세일 조건은 단기 반응을 높일 가능성이 있습니다.
다만 선택 목표가 만족도 관리이므로, 긍정률 리스크를 우선적으로 확인해야 합니다.
Action 장르는 할인 유입 이후 긍정률 하락 경향이 관찰되어 만족도 리스크를 함께 고려해야 합니다.
또한 반복 할인은 반응률 약화 가능성이 있으므로 할인 빈도 조절이 필요합니다.

근거:
- 할인율 구간 효과: p=0.004
- 시즌성 결과: 탐색적 패턴
- Action 긍정률 변화: 하락 경향, 단 확정 결론 아님
- 반복 할인: p=0.07 수준의 경향

주의:
이 결과는 예측 모델이 아니라 과거 유사 조건 기준의 전략 참고용 진단입니다.
```

## 36. 데이터 로딩 방식

웹앱에서는 원본 CSV를 직접 읽지 않고, Python 전처리 스크립트로 생성한 정적 JSON을 읽습니다.

```text
원본 CSV
  ↓
scripts/build_app_data.py
  ↓
public/data/*.json
  ↓
웹앱에서 JSON 로딩
  ↓
대시보드 / 리포트 / 시뮬레이터 표시
```

이 방식은 발표 시연 중 서버 계산이나 파일 로딩 문제를 줄이고, 정적 데이터 기반으로 안정적으로 실행할 수 있다는 장점이 있습니다.

## 42. 1순위: 데이터 로딩 + 탭 2

> 특히 자동 리포트와 시뮬레이터는 단순 템플릿이 아니라 실제 데이터 수치와 분석 근거를 함께 보여주도록 설계했습니다.

# Part K. 교수님 질문 대비 답변

## 53. 질문 1. 자동 코멘트는 그냥 템플릿 아닌가요?

답변:

> 기본 구조는 템플릿이지만, 각 문장에 선택한 게임의 실제 이벤트 수, 평균 반응률, 장르 중앙값, 시즌/비시즌 반응률 같은 수치를 넣었습니다. 따라서 모든 게임에 같은 문장이 나오는 것이 아니라, 실제 데이터에 따라 내용과 해석이 달라집니다.

---

## 54. 질문 2. 대시보드는 그냥 차트 모음 아닌가요?

답변:

> 단순 이미지 나열이 아니라 장르, 플레이타임, 시즌 여부 필터를 통해 분석 결과를 탐색할 수 있도록 구성했습니다. 동적 통계 재계산까지는 하지 않았지만, 사용자가 조건을 바꾸며 결과를 비교할 수 있는 형태로 만들었습니다.

---

## 55. 질문 3. 시뮬레이터의 규칙은 어디서 나온 건가요?

답변:

> 각 규칙은 본 분석 결과에 근거합니다. 예를 들어 할인율 관련 진단은 할인율 구간 분석에서 p=0.004로 나타난 결과를 기반으로 하고, 시즌성이나 장르 관련 진단은 탐색적 패턴으로 표시했습니다. 또한 각 진단 옆에 근거 통계와 주의 문구를 함께 제공합니다.

---

## 56. 질문 4. 이건 예측 모델인가요?

답변:

> 아닙니다. 정확한 매출이나 반응률을 예측하는 모델은 아닙니다. 과거 유사 조건에서 관찰된 패턴을 기반으로 할인 전략의 리스크를 참고할 수 있게 만든 분석 기반 진단 도구입니다.

---

## 57. 질문 5. 표본 수가 적은 장르는 어떻게 처리했나요?

답변:

> 장르별 표본 수가 다르기 때문에, 표본 수가 적은 조건에서는 결과 변동성이 클 수 있다는 경고를 함께 표시했습니다. 특히 장르 관련 결과는 확정 결론이 아니라 탐색적 패턴으로 해석하도록 안내했습니다.

---

## 58. 질문 6. 전략 목표 입력은 어디에 쓰이나요?

답변:

> 전략 목표는 계산값을 직접 바꾸기보다는 출력 리포트의 해석 우선순위를 바꾸는 역할을 합니다. 단기 유입을 선택하면 반응률 중심 코멘트를 먼저 보여주고, 장기 유지를 선택하면 유지율 리스크를, 만족도 관리를 선택하면 긍정률 리스크를 우선적으로 보여줍니다.

# Part L. 최종 결론

## 59. 최종 원칙

2, 3, 4를 합치는 것은 좋은 선택입니다.

다만 다음 원칙을 지켜야 합니다.

> Option 4는 정적/반정적 분석 대시보드  
> Option 3은 메인 output 리포트 생성기  
> Option 2는 가벼운 룰 기반 전략 시뮬레이터

여기에 추가로 다음 보완이 반드시 필요합니다.

1. 자동 해석 문장에는 실제 수치를 넣는다.

4. 장르/조건별 표본 수 경고를 넣는다.
5. 전략 목표 입력은 출력 코멘트의 우선순위에 반영한다.
6. 예측 모델처럼 보이지 않게 표현한다.
7. 앱 코드는 페이지/기능별 파일로 분리한다.
8. 데이터는 사전 가공된 정적 JSON으로 로딩한다.
