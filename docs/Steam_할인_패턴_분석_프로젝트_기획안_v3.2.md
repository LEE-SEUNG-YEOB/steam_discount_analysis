# 프로젝트 기획안 (v3.2)

## 1. 프로젝트명

**Steam 게임 가격 할인 패턴 분석을 통한 장르별 할인 효과 차이 연구**
부제: _"할인은 모두에게 똑같이 통하지 않는다"_

---

## 2. Project 소개

### 2-1. Motivation

디지털 게임 플랫폼에서는 대형 할인 행사와 정기 세일이 자주 진행된다. 일반적으로 "할인을 많이 하면 사용자 관심이 늘어난다"라고 생각하기 쉽지만, 실제로는 모든 게임이 같은 방식으로 반응하지 않을 가능성이 크다.

예를 들어 스토리 중심 게임, 경쟁형 멀티플레이 게임, 생존/샌드박스 게임은 플레이 목적과 소비 방식이 다르기 때문에 할인에 대한 사용자 관심도 변화도 다를 수 있다. 즉, 단순히 할인율이 높을수록 무조건 효과가 좋다고 보기보다는, 장르별로 어떤 할인 전략이 더 효과적인지 분석할 필요가 있다.

본 프로젝트는 게임 가격 할인 패턴과 사용자 활동 데이터를 결합하여, 장르별 할인 효과 차이를 파악하고 실제로 활용 가능한 할인 전략 인사이트를 도출하는 것을 목표로 한다.

### 2-2. Goal

본 프로젝트의 목표는 다음과 같다.

- 게임별 가격 할인 이력과 사용자 활동 지표를 수집한다.
- 할인 전후 사용자 관심도 변화를 비교하여 할인 효과를 정량적으로 분석한다.
- 장르별로 할인율과 사용자 관심도 변화의 관계가 어떻게 다른지 파악한다.
- 단순히 "할인하면 관심이 늘어난다"는 수준을 넘어서, **어떤 장르에서 어떤 할인 방식이 더 효율적인지**에 대한 결론을 제시한다.

### 2-3. 핵심 연구 질문

1. 할인율이 높을수록 사용자 관심도도 반드시 커지는가?
2. 같은 할인율이어도 장르에 따라 관심도 변화에 차이가 존재하는가?
3. 할인 직후 관심 반응은 크지만 **할인 종료 후 유지 효과가 약한** 장르가 있는가?
4. 자주 할인하는 게임과 가끔 할인하는 게임의 반응 패턴은 다른가?

### 2-4. 차별화 요소

기존의 가격 추적 사이트(SteamDB, IsThereAnyDeal 등)는 주로 **개별 게임의 가격 변동 이력**을 보여주는 데 그친다. 사용자가 한 게임씩 직접 검색해야 하고, 시장 전체의 패턴이나 할인의 실제 효과는 알기 어렵다.

본 프로젝트는 다음 네 가지에서 차별화된다:

1. **할인 정보가 아닌 할인 효과를 분석한다** — 가격 변동 자체가 아닌 그것이 사용자 관심도에 미치는 영향을 본다.
2. **개별 게임이 아닌 장르 단위로 본다** — 시장 전체의 패턴을 도출한다.
3. **"할인하면 좋다"가 아닌 "어떻게 할인해야 하는가"에 답한다** — 전략적 인사이트를 지향한다.
4. **게임사와 인디 개발자가 실제로 참고할 수 있는 실용적 결론**을 도출한다.

### 2-5. 최종 기대 결과물

- 프로젝트 발표용 PPT
- 게임 가격 할인 패턴 및 사용자 관심도 분석 결과 시각화
- 장르별 할인 반응 비교 그래프
- 할인 전략 인사이트 요약표
- 최종 결론 및 활용 방안 정리

**예상 산출물 예시**:

- 장르별 할인 반응 상위/하위 비교 차트
- 할인율 구간별 평균 반응 그래프
- 할인 직전/할인 중/할인 종료 후 사용자 활동 변화 시계열 그래프
- 장르별 추천 할인 전략 표

## 3. Project 진행 계획

### 3-1. 필요 데이터 정리

분석에 필요한 데이터는 크게 **게임 메타데이터**, **가격/할인 데이터**, **사용자 활동 데이터**, **통제 변수** 네 가지로 구분된다.

#### (1) 게임 메타데이터 — _수급 난이도: 쉬움_

| 항목            | 설명                     | 1순위 출처    | 보조/Plan B |
| --------------- | ------------------------ | ------------- | ----------- |
| 게임 ID (appid) | Steam 고유 식별자        | Steam Web API | —           |
| 게임명          | —                        | Steam Web API | Kaggle      |
| 장르 / 태그     | Steam 공식 태그          | Steam Web API | Kaggle      |
| 출시일          | 출시 후 경과 기간 계산용 | Steam Web API | Kaggle      |
| 정가            | 할인율 계산 기준         | Steam Web API | Kaggle      |
| 멀티/싱글 여부  | 통제 변수                | Steam 태그    | —           |

#### (2) 가격 / 할인 데이터 — _수급 난이도: 중간_

| 항목               | 설명             | 1순위 출처         | 보조/Plan B          |
| ------------------ | ---------------- | ------------------ | -------------------- |
| 할인율             | % 단위           | IsThereAnyDeal API | Kaggle 할인 데이터셋 |
| 할인 시작일·종료일 | 시계열 분석 필수 | IsThereAnyDeal API | Kaggle               |
| 과거 할인 이력     | 할인 빈도 계산용 | IsThereAnyDeal API | Kaggle               |

→ Steam 공식 API는 현재 가격만 제공하므로, 할인 이력은 **IsThereAnyDeal API를 메인**으로 사용한다. API 키 발급이 지연될 경우 Kaggle의 할인 이력 데이터셋을 Plan B로 활용한다.

#### (3) 사용자 활동 데이터 — _수급 난이도: 어려움 ⚠️_

이상적으로는 동시 접속자 수 시계열이 좋지만, 과거 이력을 무료로 받기 어렵다. 따라서 다음 우선순위로 접근한다:

| 우선순위         | 지표                            | 출처                                      | 비고                                                                                                                     |
| ---------------- | ------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **1순위 (메인)** | **리뷰 작성 수의 일별 시계열**  | Steam Web API `appreviews`                | 리뷰마다 작성일자가 있어 "할인 기간에 사용자 활동이 평소 대비 얼마나 늘었는가"를 측정 가능. **무료, 안정적, 추출 쉬움.** |
| 2순위 (보조)     | 동시 접속자 수 (현재값)         | Steam Web API `GetNumberOfCurrentPlayers` | 현재 시점만 가능. 시계열 X.                                                                                              |
| 3순위 (대체)     | 동시 접속자 수 시계열           | Kaggle "Steam Charts" 데이터셋            | 데이터셋이 있으면 활용, 없으면 패스                                                                                      |
| 4순위 (보강)     | 추정 소유자 수, 평균 플레이타임 | SteamSpy API                              | 추정치라 정밀도 낮음. 보조 지표로만 사용.                                                                                |

→ **메인 지표는 "리뷰 작성 수 증가율"로 확정**.

**중요**: 본 프로젝트에서 "리뷰 작성 수"는 신규 유입 유저 수를 직접 측정하는 것이 아니라, **"해당 기간 동안 게임에 대한 사용자 활동·관심도가 얼마나 활발해졌는가"** 를 측정하는 대리 지표(proxy)로 사용한다. 리뷰는 게임을 실제로 플레이한 사용자만 작성할 수 있으므로, 리뷰 작성량의 변화는 그 시기에 게임을 능동적으로 소비한 사용자의 규모를 간접적으로 반영한다.

#### (4) 통제 변수 — _발표 방어력의 핵심_

할인 효과를 분석할 때, 할인 외에도 사용자 활동에 영향을 줄 수 있는 변수들이 존재한다. 분석 시 다음 변수들을 통제 변수로 함께 고려하여 할인의 순수 효과를 분리한다:

| 통제 변수                    | 우선도 | 이유                                                                                   |
| ---------------------------- | ------ | -------------------------------------------------------------------------------------- |
| **대형 시즌 세일 기간 여부** | 필수   | 여름/가을/겨울 세일은 모든 게임이 동시에 노출되어 평시 할인보다 효과가 클 수 있음      |
| **출시 후 경과 기간**        | 필수   | 신작은 할인과 무관하게 초기 리뷰가 폭발적으로 증가하는 경향이 있음                     |
| **전체 리뷰 수 (인기도)**    | 필수   | 인기 게임은 작은 할인에도 절대 변화량이 큼 → 절대값이 아닌 비율로 측정                 |
| **멀티/싱글 여부**           | 필수   | 멀티플레이 게임은 커뮤니티·이벤트 영향이 더 클 수 있음                                 |
| **최근 패치/업데이트 시기**  | 보조   | 수집 가능한 범위 내에서 보조 변수로 고려. 시간 제약상 필수 통제 변수로는 사용하지 않음 |

이러한 통제 변수를 분석에 함께 고려함으로써 "그 반응이 정말 할인 때문인가, 아니면 다른 요인 때문인가"라는 비판에 대응할 수 있다.

#### (5) 분석 대상 규모

장르 분류는 **Steam 공식 태그를 기반으로 다음 5개 대분류로 재매핑**하여 분류 기준의 일관성을 유지한다:

- **Action** (액션, FPS, 격투, 슈팅 등)
- **RPG** (Action RPG, JRPG, CRPG 등 모든 RPG 하위 장르 포함)
- **Strategy / Simulation** (실시간/턴제 전략, 도시·경영·생활 시뮬 등)
- **Adventure** (어드벤처, 비주얼 노벨, 내러티브 중심)
- **Casual / Indie** (퍼즐, 캐주얼, 소규모 인디 작품)

각 장르당 10개씩, **총 50개**로 1차 분석을 진행한다. 장르당 표본이 10개 미만이면 통계적 비교의 신뢰도가 떨어지므로 이 수준을 최소선으로 유지한다. 시간 여유가 있을 경우 장르당 12~15개로 확장한다(최대 60~75개).

### 3-2. 작업 방식

#### 1단계: 데이터 수집

- Steam Web API로 분석 대상 게임 50개의 메타데이터 수집 (장르 균형 고려)
- IsThereAnyDeal API로 각 게임의 할인 이력 수집
- Steam `appreviews` API로 게임별 리뷰 작성일 수집
- (Plan B) API 막힐 시 Kaggle Steam 데이터셋에서 보조 데이터 확보

#### 2단계: 데이터 전처리

- 중복 데이터 제거
- 날짜 형식 통일 (UTC 기준)
- 할인 기간과 리뷰 작성일 매칭
- 장르 분류 정리 (Steam 태그를 5개 대분류로 통합)
- 통제 변수 플래그 생성 (시즌 세일 여부, 출시 후 경과 일수 등)
- 분석용 통합 데이터프레임 생성

#### 3단계: 탐색적 분석 (EDA)

- 할인율 분포 확인
- 장르별 게임 수, 평균 정가 분포 확인
- 할인 전후 리뷰 작성 수 패턴 시각화

#### 4단계: 본 분석

- **할인 반응률 및 유지 반응률 계산** (정의는 아래 3-3 참조)
- 할인율과 반응률 간 상관관계 분석
- 장르별 평균 반응률 비교 (통제 변수 고려)
- 시즌 세일 vs 평시 할인 비교
- 할인 빈도와 반응률의 관계 분석
- 장르별 "할인 효과 큰 그룹 / 작은 그룹" 분류
- **할인 반응률 vs 유지 반응률 비교**로 "단발성 효과 장르 vs 지속 효과 장르" 식별

#### 5단계: 시각화 및 발표 자료 제작

- 핵심 그래프 4~5개 제작
- 인사이트 정리
- PPT 통합 및 발표 스크립트 작성

### 3-3. 분석 방법

복잡한 머신러닝 모델보다 **설명 가능한 통계 분석** 위주로 진행한다.

- 할인 전후 평균 변화율 비교
- 장르별 그룹 비교 분석
- 상관관계 분석 (Pearson / Spearman)
- 시즌 세일 / 평시 할인 분리 비교
- 단순 회귀 또는 범주별 비교 분석
- 시계열 변화 시각화

**핵심 지표 정의**:

본 프로젝트는 할인의 **즉시 효과**와 **유지 효과**를 분리해서 측정하기 위해 두 가지 지표를 함께 사용한다.

```
[지표 1] 할인 반응률 (즉시 효과)
= (할인 기간 중 일평균 리뷰 수 - 할인 직전 30일간 일평균 리뷰 수)
  ÷ 할인 직전 30일간 일평균 리뷰 수

[지표 2] 유지 반응률 (지속 효과)
= (할인 종료 후 14일간 일평균 리뷰 수 - 할인 직전 30일간 일평균 리뷰 수)
  ÷ 할인 직전 30일간 일평균 리뷰 수
```

- **지표 1 (할인 반응률)**: 할인이 진행되는 동안 사용자 활동이 얼마나 폭증했는지를 본다.
- **지표 2 (유지 반응률)**: 할인이 끝난 후에도 사용자 활동이 평소보다 높게 유지되는지를 본다. 할인 종료 직후의 단기 잔존 효과를 관찰하기 위한 관찰창으로 **14일**을 설정하였다(다음 할인 사이클이나 외부 이벤트의 영향을 최소화하기 위해 너무 길지 않은 기간으로 설정).

두 지표를 함께 비교하면, 단순히 "할인 중에만 반짝 효과가 있는 장르"와 "할인 이후에도 사용자 활동이 비교적 유지되는 장르"를 구분할 수 있다. 이는 연구 질문 3번("유지 효과가 약한 장르가 있는가?")에 직접적으로 답하는 핵심 분석이다.

두 지표 모두 절대값이 아닌 **비율**을 사용하므로 인기도가 다른 게임 간 비교가 가능하다.

### 3-5. 예상 결과 (가설)

- 할인율이 높다고 해서 사용자 관심도가 항상 비례해 증가하지는 않을 것이다.
- 장르에 따라 할인 효과가 크게 다를 가능성이 높다.
- 스토리 중심 또는 진입장벽이 낮아지는 장르(Adventure, RPG 등)는 할인 효과가 크게 나타날 수 있다.
- 반면 경쟁형 멀티플레이 게임(Action 장르 일부)은 할인율보다 커뮤니티 활성도, 업데이트, 이벤트의 영향이 더 클 수 있다.
- 일부 장르는 할인 중 즉시 반응은 크지만 유지 반응률은 낮을 것으로 예상되며, 반대 패턴을 보이는 장르도 존재할 수 있다.
- 시즌 세일과 평시 할인의 효과 차이는 장르마다 다를 수 있다.

→ 최종적으로 **"모든 게임에 동일한 할인 전략을 적용하는 것은 비효율적이며, 장르별 맞춤 할인 전략이 필요하다"** 는 결론을 도출하는 것을 목표로 한다.

### 3-6. 본 연구의 한계 ⚠️

본 프로젝트는 학생 과제 수준의 시간·자원 제약 내에서 진행되므로, 다음과 같은 한계를 명확히 인식하고 있다:

1. **대리 지표의 한계**: 본 프로젝트는 리뷰 작성 수를 사용자 활동의 대리 지표(proxy)로 사용하므로, 실제 플레이 시간이나 정확한 신규 구매 전환을 직접 측정하지는 못한다. 따라서 본 분석 결과는 "할인 기간 동안의 사용자 관심·활동량 변화"를 의미하며, "구매 전환율"이나 "매출 효과"와는 구분되어 해석되어야 한다.
2. **표본 수 한계**: 50개의 표본은 시장 전체를 대표하기에는 작은 규모이며, 본 연구는 전체 패턴 도출이 아닌 **탐색적 비교 분석**의 성격을 가진다.
3. **통제의 불완전성**: 할인 외에 사용자 활동에 영향을 미치는 모든 변수를 완벽히 통제하지는 못하며, 특히 패치/업데이트, 외부 이벤트(스트리머 방송, 출시 기념일 등)의 영향은 부분적으로만 고려된다.

이러한 한계는 후속 연구에서 더 큰 표본과 정밀한 데이터(동시 접속자 시계열, 매출 데이터 등)를 통해 보완될 수 있다.

### 3-7. 단계별 실행 파이프라인

본 프로젝트의 실제 실행 순서를 11단계로 세분화한 파이프라인이다. 각 단계는 결과물(CSV 등)을 남겨 다음 단계로 안전하게 이어진다.

#### Step 1. 환경 세팅

- VS Code + Python 가상환경(`venv`) 구성
- 라이브러리 설치: `requests`, `pandas`, `numpy`, `matplotlib`, `seaborn`, `python-dotenv`, `tqdm`, `jupyter`, `ipykernel`
- 프로젝트 폴더 구조 생성: `data/`, `notebooks/`, `src/`, `docs/`
- `.env`에 API 키 저장, `.gitignore`로 키·가상환경 제외
- GitHub 비공개 저장소 연동 및 팀원 Collaborator 초대

#### Step 2. 분석 대상 게임 리스트 확보

- Steam 인기 게임 중 5개 장르 × 10개씩 = 총 50개 후보 선정
- 선정 기준: 리뷰 1만 개 이상, 출시 1년 이상 경과
- 결과: `target_games.csv` (appid, 게임명, 장르 카테고리)

#### Step 3. 게임 메타데이터 수집

- Steam Web API `appdetails`로 각 게임의 메타데이터 수집
- 수집 항목: 장르, 출시일, 정가, 태그, 멀티/싱글 여부
- rate limit 대응을 위한 sleep 적용
- (Plan B) 막힐 시 Kaggle Steam 데이터셋
- 결과: `data/game_metadata.csv`

#### Step 4. 할인 이력 수집

- IsThereAnyDeal API로 각 게임의 과거 할인 이력 수집
- 수집 항목: 할인 시작일, 종료일, 할인율
- (Plan B) 막힐 시 Kaggle 할인 이력 데이터셋
- 결과: `data/discount_history.csv`

#### Step 5. 리뷰 데이터 수집 ⭐

- Steam `appreviews` API로 게임별 리뷰 페이지네이션 수집
- 수집 필드: `timestamp_created`, `voted_up`, `playtime_at_review`
- 게임당 최근 1~2년 리뷰로 제한 (수집 시간 절약)
- 가장 시간이 오래 걸리는 단계 — 진행률 표시(`tqdm`) 필수
- 결과: `data/reviews_raw.csv`

#### Step 6. 데이터 전처리

- 날짜 형식 통일 (UTC → datetime)
- 장르 5개 대분류 매핑 (예: Action RPG → RPG)
- 할인 기간과 리뷰 작성일 매칭 인덱싱
- 결측치·중복 처리
- 결과: `data/cleaned_dataset.csv`

#### Step 7. 통제 변수 플래그 생성

- 각 할인 이벤트마다 다음 플래그 추가:
  - `is_seasonal_sale`: Steam 공식 시즌 세일 기간 여부
  - `days_since_release`: 출시 후 경과 일수
  - `total_review_count`: 시점별 누적 리뷰 수 (인기도 proxy)
  - `is_multiplayer`: 멀티플레이 여부
- 결과: `data/discount_events_with_controls.csv`

#### Step 8. 핵심 지표 계산

- 각 할인 이벤트마다 **할인 반응률**과 **유지 반응률** 계산
  - 할인 직전 30일 일평균 리뷰 수
  - 할인 기간 일평균 리뷰 수
  - 할인 종료 후 14일 일평균 리뷰 수
  - 두 지표를 비율로 산출
- 결과: `data/discount_response.csv`

#### Step 9. 본 분석

- 할인율 vs 반응률 산점도 + 상관계수
- 장르별 평균 반응률 비교 (bar chart)
- 시즌 세일 vs 평시 할인 분리 비교
- 출시 경과 기간으로 그룹 나눠 분석 (신작 vs 구작)
- 할인율 구간별 평균 반응률 (0~25%, 25~50%, 50~75%, 75%+)
- 할인 반응률 vs 유지 반응률 비교로 단발성/지속성 장르 식별
- 시계열 시각화 (할인 전후 7일 리뷰 수 변화)

#### Step 10. 인사이트 도출 및 시각화 정리

- 의외의 발견 3가지 추리기
- 발표용 차트 4~5개 깔끔하게 다시 그리기 (한글 폰트, 컬러 통일)
- 결과: `figures/` 폴더에 PNG 저장

#### Step 11. 결론 정리 및 발표 자료 제작

- 장르별 추천 할인 전략 표 작성
- PPT 결과 슬라이드에 차트 통합
- 발표 스크립트 작성 및 리허설

## 4. 구성원 R&R (2인 기준)

### 팀원 A — 데이터 수집·전처리 + PPT 제작

**데이터 파트**

- Steam Web API / IsThereAnyDeal API 연동 및 데이터 수집 (Step 3~5)
- 게임 메타데이터, 할인 이력, 리뷰 데이터 raw 확보
- 데이터 전처리: 결측치·중복 제거, 날짜 형식 통일, 장르 5개 대분류 매핑 (Step 6)
- 통제 변수 플래그 생성 (Step 7)
- 분석용 통합 데이터셋 생성 → 팀원 B에게 전달

**PPT 파트**

- PPT 전체 디자인 및 슬라이드 제작
- Motivation, Goal, 차별화 요소, 방법론 슬라이드 구성
- 팀원 B의 분석 결과·시각화를 받아 결과 슬라이드에 통합
- 발표 자료 최종 검수 및 디자인 마감

### 팀원 B — 분석·시각화 + 발표

**분석 파트**

- 팀원 A가 전달한 정제 데이터셋으로 본 분석 수행 (Step 8~9)
- 할인 반응률·유지 반응률 계산
- 장르별 평균 비교, 시즌 세일 vs 평시 할인 비교, 상관관계 분석
- 통제 변수를 고려한 그룹별 분석
- 핵심 인사이트 3가지 도출

**시각화 파트**

- matplotlib / seaborn으로 발표용 차트 4~5개 제작 (Step 10)
- 장르별 반응률 비교 차트, 할인율 구간별 그래프, 시계열 그래프 등
- 한글 폰트·컬러 통일하여 PPT에 바로 삽입 가능한 형태로 마감
- 시각화 이미지 + 결론 문장 → 팀원 A에게 전달

**발표 파트**

- 발표 스크립트 작성 (Step 11)
- 분석 흐름과 결론을 직접 이해하고 설명할 수 있도록 정리
- 리허설 진행 (15분 한도 체크)
- 발표 당일 Q&A 대응

### 작업 흐름 (병렬 처리)

```
[A: 데이터 수집·전처리]  →  [B: 분석·시각화]  →  [A: PPT 통합]  →  [B: 발표 준비]
       ↓                          ↓                    ↓
   raw data CSV          정제 데이터 받음        시각화·결론 받음
                          ↓                              ↓
                     A는 동시에 PPT 골격 작업       B는 동시에 스크립트 작업
```

**핵심 원칙**: A의 데이터 수집이 끝나기 전부터 PPT 골격(Motivation·Goal·방법론 슬라이드)은 미리 만들어두고, B는 데이터 받자마자 분석 시작. 즉 **순차가 아닌 병렬**.
